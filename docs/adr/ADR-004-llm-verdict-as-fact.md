# ADR-004: Вердикт LLM попадает в FSM как факт

* **Статус:** Принято
* **Дата:** 2025-04-27
* **Контекст:** Срез 1, проектирование команд FSMService.

## Контекст

В обучающем тренажёре есть точки, где правильность ответа сотрудника
определяется LLM:

* `TRAINING_QUIZ` — оценка ответа на проверочный вопрос.
* `PRACTICE_EVAL` — оценка диалога-практики по чек-листу.

Возникает вопрос: **где** именно эта оценка происходит и **в каком
виде** результат попадает в FSM.

Варианты:

1. **Команда несёт сырой текст.** `SubmitAnswer(text="...")` приходит
   в `FSMService`. Сервис вызывает LLM, получает вердикт, эмитит
   событие `ALL_CORRECT` / `HAS_ERRORS`.
2. **Команда несёт вердикт-факт.** `SubmitQuizAnswer(correct: bool)`.
   LLM вызывается на слое выше (контроллером / use-case'ом). FSM
   получает уже готовое решение.

## Решение

Принят **вариант 2**: команды несут вердикт как факт.

```python
@dataclass(frozen=True)
class SubmitQuizAnswer:
    correct: bool

@dataclass(frozen=True)
class PracticeEvaluated:
    weak_zones: tuple[str, ...]  # пустой = все зоны OK
```

## Обоснование

1. **FSMService остаётся чистой функцией.** Никаких сетевых вызовов,
   никаких асинхронных эффектов внутри домена. Это критично для
   тестируемости — тесты не нуждаются в моках LLM.
2. **LLM — внешний сервис, отказы и таймауты возможны.** Их обработка
   (ретраи, fallback, логирование) — задача слоя контроллера, не FSM.
3. **Разделение ответственностей.** FSM знает «как структурирован
   процесс», LLM знает «правильный ли ответ». Смешивать слои в одной
   функции — путь к спагетти.
4. **Тесты FSM тривиальны.** `SubmitQuizAnswer(correct=True)` —
   очевидный случай. Не нужно мокать LLM, чтобы проверить переход.

## Последствия

* Контроллер обязан **до** вызова `FSMService.handle` получить вердикт
  LLM и сформировать соответствующую команду.
* Если LLM упал — это решение контроллера: ретраить, показать ошибку,
  считать ответ некорректным. FSM в эту ветку не попадает.
* Команды типа `SubmitDialogTurn(text)` или `SubmitAnswer(text)`
  **не существуют** в `application/commands.py`. Они были в раннем
  прототипе и удалены при пересмотре архитектуры.

## Альтернативы

Вариант 1 («команда с сырым текстом») рассматривался и отвергнут:
он смешивает оркестрацию с интеграцией, делает FSM асинхронной и
размывает границы тестов.

# Roadmap

План реализации MVP по вертикальным срезам. На каждом срезе система
работает целиком (для своего уровня абстракции). Каждый срез завершается
зелёными тестами и обновлением документации.

Перед каждым новым срезом — пересмотр и уточнение деталей следующего среза.
Срезы могут быть разделены на под-срезы по ходу работы.

## Срез 1. FSM-ядро в памяти

**Цель:** домен и оркестратор FSM работают как чистый Python-код.

- `domain/`: states, events, transitions, context.
- `application/`: commands, effects, fsm_service.
- Тесты: pytest, всё в памяти, без БД и LLM.
- Документация: `ARCHITECTURE.md`, `DECISIONS.md` обновляются по ходу.

**Критерий завершения:** можно прогнать любой сценарий из FSM
(включая петлю Пример→Практика→Знание) последовательностью команд
и убедиться в правильности переходов. Покрытие тестами — 100% переходов.

## Срез 2. Persistence

**Цель:** сессии сохраняются между шагами.

- `infrastructure/persistence/`: SessionStore (Postgres + SQLAlchemy).
- Alembic-миграция для таблицы сессий.
- Тесты: integration с реальной БД (через docker compose).
- Новый документ: `docs/DATA.md` со схемой БД.
- Новый документ: `docs/DOMAIN.md` с подробным описанием FSM.

**Критерий завершения:** можно создать сессию, прогнать через несколько
команд, перезапустить приложение, продолжить с того же места.

## Срез 3. Заглушка LLM

**Цель:** FSM работает с фейковым LLM, можно прогнать end-to-end сценарий.

- `infrastructure/llm/`: интерфейс `LLMClient`, реализация `FakeLLMClient`.
- Эффекты FSM, требующие LLM (генерация реплики, оценка диалога),
  начинают исполняться адаптером.
- Тесты: end-to-end сценарий «полный путь сотрудника» с фейковым LLM.

**Критерий завершения:** один тест прогоняет полный happy path
(MENU → TRAINING → TRAINING_QUIZ → ... → TRAINING_COMPLETE) и один тест
прогоняет петлю ремедиации.

## Срез 4. Минимальный HTTP API

**Цель:** тренажёр доступен через HTTP без UI.

- `infrastructure/web/`: FastAPI-приложение, эндпоинты `/training/*`.
- Запуск через uvicorn, тестирование через curl/HTTPie.
- Новый документ: `docs/API.md` с контрактами эндпоинтов.

**Критерий завершения:** через curl можно создать сессию, отправлять
команды, получать ответы и эффекты в JSON.

## Срез 5. Минимальный UI тренажёра

**Цель:** сотрудник может пройти обучение через браузер.

- Frontend: пока без TTS/STT, без аватара, без PDF — просто чат.
- Кнопки переключения режимов.

**Критерий завершения:** на VPS или локально можно открыть браузер,
ввести имя, пройти обучение от начала до конца с фейковым LLM.

## Срез 6. Реальный GigaChat

**Цель:** заменить заглушку LLM на настоящий GigaChat.

- `infrastructure/llm/`: реализация `GigaChatClient`.
- Промпты пока хардкодом или в YAML (админка ещё не готова).

**Критерий завершения:** обучение проходит с реальным AI.

## Срез 7. Голос (SaluteSpeech)

**Цель:** TTS и STT в тренажёре.

- `infrastructure/speech/`: клиент SaluteSpeech.
- Frontend: кнопка записи, плеер озвучки.
- Аватар, PDF-презентация в UI.

**Критерий завершения:** обучение можно пройти голосом.
**Статус:** TTS ✅, STT ✅ (через `/api/stt`, MediaRecorder + SaluteSpeech).

## Срез 8. Админка промптов

**Цель:** владельцы продуктов могут править промпты без разработчика.

- `infrastructure/web/`: эндпоинты `/admin/*`, аутентификация.
- Хранилище промптов в БД, привязка к продукту и режиму.
- Frontend: логин-форма, список промптов, редактор.
- Промпты загружаются из БД (а не из YAML).

**Критерий завершения:** владелец продукта логинится, правит промпт,
запускает тренажёр в другой вкладке — изменения видны.

## Срез 9. Деплой на VPS

**Цель:** прототип работает на VPS владельца проекта.

- Dockerfile для production-сборки.
- nginx как reverse proxy.
- Скрипт/инструкция для деплоя.
- HTTPS-сертификат.

**Критерий завершения:** прототип доступен по публичному URL.

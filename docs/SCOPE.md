
# Scope MVP

Документ описывает границы MVP. Всё, что **не** упомянуто здесь как
«входит в MVP», по умолчанию **не входит** и не должно реализовываться
без явного решения и записи в `DECISIONS.md`.

## Что делает система (бизнес-функции)

Сотрудник банка обучается продаже банковского продукта (на старте — только
один продукт: «Кредитная карта, новичок») в формате интерактивного тренажёра
с AI-наставником.

Сотрудник может выбрать один из четырёх режимов:

- **Обучение** — теория с проверочными вопросами.
- **Пример** — диалог с AI, где AI играет роль сотрудника банка, а пользователь — клиента.
- **Практика** — диалог с AI, где AI играет роль клиента, а пользователь — сотрудника банка. По итогам — оценка по чек-листу.
- **Знание** — отработка западающих зон, выявленных в Практике.

Если сотрудник проходит Практику неуспешно, система автоматически проводит
его по петле «Пример → Практика → Знание» до тех пор, пока Практика не
будет пройдена успешно.

Подробное описание FSM — см. `docs/DOMAIN.md` (будет создан на Срезе 2).

## Что входит в MVP

### Тренажёр (роль: сотрудник банка)

- Web-интерфейс по адресу `/training`.
- Стартовое меню: ввод имени, выбор продукта, кнопка «Начать обучение».
- Стартовое сообщение от AI-наставника.
- Четыре режима с кнопками переключения.
- Чат с репликами AI и пользователя.
- **Озвучка реплик AI** через SaluteSpeech (TTS).
- **Захват голоса пользователя** через SaluteSpeech (STT).
- Аватар AI справа в верхнем углу.
- PDF-презентация продукта в интерфейсе.
- Хранение состояния сессии в БД (сотрудник может вернуться к обучению).
- Проверочные вопросы в режиме «Обучение» с разбором ошибок.
- Оценка диалога в режиме «Практика» через LLM.
- Автоматическая петля «Пример → Практика → Знание» при неуспешной Практике.

### Админка (роль: владелец продукта)

- Web-интерфейс по адресу `/admin`.
- Аутентификация: логин и пароль.
- CRUD промптов LLM, привязанных к продукту и режиму.
- Базовая валидация (промпт не пустой и т. п.).

### Инфраструктура

- LLM: GigaChat (с фазой разработки на заглушке).
- Голос: SaluteSpeech.
- БД: PostgreSQL.
- Деплой: на VPS владельца проекта (детали — на Срезе 9).
- Один продукт: «Кредитная карта, новичок».

## Что НЕ входит в MVP

Список сознательно отброшенного. Если что-то из этого станет нужным —
заводится ADR в `DECISIONS.md` с обоснованием.

- Несколько продуктов (на старте только один: КК-новичок).
- Аутентификация сотрудников (только ввод имени).
- SSO с банковскими системами.
- Версионирование промптов с историей и откатом
  (только перезапись текущей версии).
- Мобильное приложение.
- Telegram-бот.
- Аналитика и дашборды по сотрудникам.
- Импорт фактологии из DOCX/PDF на лету
  (контент готовится вручную и кладётся в `content/`).
- Многоязычность (только русский).
- Резервное копирование БД, мониторинг, алерты
  (для прототипа на VPS — позже).
- Нагрузочное тестирование, оптимизация
  (для прототипа достаточно работающей логики).
- Контроль и ограничение расходов на LLM/SaluteSpeech.
- Роли в админке (все владельцы продуктов имеют одинаковые права).
